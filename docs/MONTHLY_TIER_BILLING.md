# 月度分段计费

月度分段计费为 Anthropic 标准余额分组提供按用户、分组和北京时间自然月
累计的两档倍率。它替代该分组的固定分组倍率和用户专属倍率，不与它们叠加。

## 规则

- 每个用户在同一分组下的所有 API Key 合并累计。
- 以结算时间所在的北京时间自然月归属；每月 1 日自动从第一档重新开始。
- `threshold` 以内的原价消费乘 `first_rate`，超过门槛的部分乘 `excess_rate`。
- 单笔请求跨越门槛时按两段拆分。累计原价与实际扣款均保留可审计记录。
- 首次启用从保存规则的 `starts_at` 之后开始，不追溯启用前的本月历史消费。
- 月度规则关闭后保留累计数据；重新启用沿用原起始时间和当月累计。
- 订阅分组及非 Anthropic 分组不能启用此规则。

例如门槛为 500、第一档 0.7、超出档 1.2：本月原价累计 490 后再结算
30，实际扣款为 `10 × 0.7 + 20 × 1.2 = 31`。

## 管理与用户入口

管理员在分组编辑页打开“月度阶梯计费”，填写门槛和两档倍率。用户在用量页
查看自己的当月原价累计、已扣金额、剩余额度、当前倍率和下次重置时间。
服务端从认证用户身份读取进度，不接受客户端指定其他用户。

## 数据一致性与回滚

迁移 `233_monthly_tier_billing.sql` 只增加策略字段、月度累计表和永久结算流水，
默认关闭，不修改已有余额或历史用量。每次扣费在同一数据库事务内完成幂等检查、
月度行加锁、分段计算、余额扣款和 Key 配额计数；重复请求不会重复结算。若后续
账号额度操作失败，余额、累计和流水一并回滚。

发布回滚时可切回旧应用并关闭月度规则；不要用旧数据库备份覆盖上线后产生的
余额、订单或结算数据。保留新表和增量数据，按结算流水核对后再处理数据库恢复。

## 验证

后端单元测试覆盖跨门槛计算、校验和认证缓存版本；PostgreSQL 集成测试覆盖并发
双 Key、重复结算、跨月、用户隔离、事务回滚和极小金额 Key 计数；前端组件测试、
类型检查和生产构建均应在发布前通过。
